# 020 secondary arms (pre-declared DESCRIPTIVE, docs/09 decision 5)

Files: `extract.py` (prep, features, D-008 guard, parity), `analyze.py` (all three arms), `tables.py`; outputs `results/secondary.json`, `results/{d008_guard,parity}.json`, `tables.md`, logs. Features: `cache/` (git-ignored, `.gitignore` here). Frozen 020 `run.py`, `config.json` and `results/` were not modified (run.py imported by path; `run.RES` redirected while building the analyses; fold hashes re-derived equal `results/folds_commit.json`). No label is assigned and no 020 verdict changes.

## What was done
- **Features** for 900 new Synthbuster images (SD1.3, SD1.4, GLIDE; 300 caption families each, the same 300 for all three, 157 of them also used by the old 1020 fakes) at the 5 fov512 conditions, and 1600 new RAID fakes (400 ids x gen_0..3) at fov224 clean / jpeg(75) / jpeg(90) (jpeg(90) is needed because the frozen RAID T-mix includes it). Pipeline = 004: `perturb.apply_condition(key = raw sha256, seed 0)`, DINOv2-base blocks 4/8/12 CLS+mean (4608-d), fp32, TF32 off, batch 20, same shard writer and meta check. Prep: `lib/preprocess.process_image(mode="fov")`.
- **D-008 guard** (32 new images per universe, cached GPU features vs CPU recomputation, batch 4): max scaled feature diff 3.7e-05, max |dlogit| of the 020 b8 probe (8-way for fov512, 4-way for fov224, C=0.01, T-mix) 6.7e-05; tolerance 1e-3, all 8 universe/condition cells ok (`results/d008_guard.json`).
- **Parity**: 16 existing fov512 fakes (2 per generator) x 5 conditions and 16 existing RAID fakes x {clean, jpeg(75)} re-extracted through this script versus the existing 004/016/019 caches: max scaled diff 6.4e-06 (tolerance 1e-3). The raw files re-processed with `process_image` give pixel-identical PNGs to the existing processed images (32/32). `results/parity.json`.
- **Arms** reuse the 020 functions by import: `make_folds` (5-fold StratifiedGroupKFold by caption family / RAID id), `closed_task` + `inner_table` (standardised balanced LR, C by inner 3-fold grouped CV, same C grid), `nested_logp`, `eval_closed`, `auroc_boot`, `cluster_weights` (1000 cluster bootstraps, seed 0).

## Deviations (none affects a frozen criterion)
1. **GLIDE is 256x256.** fov512 never upscales (`process_image` returns skipped_small). I upscaled 2x with PIL BICUBIC to 512 and then ran the unchanged fov512 pipeline. GLIDE rows are therefore not comparable to the 8 trained classes in resampling history; its predictions (below) are confounded by that.
2. The forward loop retries on CUDA OOM with a halved batch (GPU shared with the VAE job) instead of `features.embed_images`' sticky CPU fallback; same `bb.to_tensor`/`bb.forward`. No OOM was logged.
3. Near-twin arm: the 020 `closed_task` is run unchanged with K=2 (feature sets b8 and cat, each separately, no nested set choice). A clean-train regime is added as a sensitivity row. A label-swap-within-family null (60 shuffles, b8, C=0.01) gives the empirical chance level.
4. Q3 final probe: the feature set (b4/b8/b12/cat) and C are chosen by inner grouped 3-fold CV on all 1020 fakes at jpeg75_resize05 (same tie rule as `nested_logp`); the choice is cat, C=0.1 (inner bacc 0.846). b8 is shown as sensitivity.
5. RAID: the "without gen_0" figures are (i) macro recall over gen_1..3 of the 4-way model (the 020 `drop_macro` convention) and (ii) a fresh 3-way probe trained on gen_1..3 only. The 020 n=100 reference is 0.688 [0.650, 0.725].

## Findings (descriptive; CIs in tables.md)
- **Q2 near-twin: SD1.3 vs SD1.4 is not separable.** bacc 0.49 to 0.55, every CI includes 0.5 or sits at its edge; the best cell is b8 at jpeg75_resize05 (bacc 0.527 [0.490, 0.562], AUROC 0.535 [0.498, 0.573], 2-AFC 0.557 [0.500, 0.613]), inside the label-swap null (p95 0.54, max 0.56). Same in the 11-way probe: SD1.3 and SD1.4 images are called "SD1.3 or SD1.4" 94% / 92% of the time (jpeg75_resize05) but split about 50/50 between the two; their pairwise 2-AFC is 0.503.
- **Q3 family.** In the 8-way probe SD1.x images do not go cleanly to stable-diffusion-2: the plurality is SD2 at clean (0.34 and 0.36) and social_sim (0.35, 0.37), but at jpeg75_resize05 it is midjourney-v5 (0.41, 0.40) with SD2 at 0.28 and 0.24; SDXL gets 0.01 to 0.10, SD3 0.11 to 0.17. The mass is spread, so the SD1.x -> SD2 link is weak and not stable across conditions. In the 11-way probe SD1.x forms its own tight cluster (SD2 recall stays 0.71, almost no SD1.x -> SD2), so the probe sees SD1.x as a separate family from SD2; it does not tell whether this is a decoder trace or an image-statistics difference (SD1.x are native 512, SD2/SDXL raw images are about 1 MP and non-square, resized to 512 by fov512, a resampling-history difference between the classes).
- **GLIDE** is predicted DALL-E 2 by 91% / 92% / 98% (clean / jpeg75_resize05 / social_sim; b8: 63% / 79% / 83%); the 11-way probe finds GLIDE trivially (recall 0.98). Treat as confounded: the 2x bicubic upscale gives a smooth low-detail look that DALL-E 2 (1024 downscaled to 512) also has. A GLIDE -> DALL-E 2 lineage reading is not testable here.
- **11-way closed set**: bacc 0.765 [0.747, 0.783] at jpeg75_resize05 (chance 0.091), 0.839 clean; the 8 old classes keep their recalls, only SD1.3/SD1.4 are low (0.46 / 0.49) because of mutual confusion.
- **RAID n=500 (2000 fakes)**: 4-way bacc 0.772 [0.756, 0.789] at jpeg(75), T-mix (n=100 reference 0.688); old-100-id subset of the same OOF 0.783, new 400 ids 0.770, so the replication holds on fresh ids. Without gen_0: macro recall gen_1..3 of the 4-way model 0.719 [0.698, 0.739] (chance 0.25), fresh 3-way 0.736 [0.715, 0.756] (chance 0.333); gen_0 recall 0.93. The gen_0 size cue (all 400 new gen_0 are exactly 256x256, the other gens are 512x512, 640x480, 640x360) is a shortcut for the 4-way number (gen_0 recall 0.93), but the 3-way result stays well above chance, as in the critic's c3. gen_k -> generator mapping remains [unverified]. Clean-train transfer to jpeg(75) is 0.497 (4-way), the same collapse as in 020.
- Caveat: the 2-AFC pairwise numbers (RAID 0.956, 3-way 0.913) are the easy matched-pair metric; the strict reading was not rerun here.
